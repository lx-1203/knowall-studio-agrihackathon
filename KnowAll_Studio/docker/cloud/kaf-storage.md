# 加密资料迁移与恢复

KAF 下载和授权从当前账号的 `DOCUMENT_DIR/kaf/<file_id>.kaf` 读取；数据库 `storage_path` 保留发布时的路径作历史记录，不参与下载定位。因此停机迁移完整数据根后，旧索引无需改写绝对路径。默认目录和已有环境配置不变。

必须保留原文件字节以及同一账号的 `kaf_keys/account_priv.pem.enc`、`kaf_keys/account_pub.pem`、`.secret_key`，并一起恢复数据库。仅搬资料、重新生成密钥或混入另一账号的密钥，不能解密原资料。云端每个账号拥有独立工作目录；不能把所有个人进程指向同一个私钥目录。账号登录令牌还依赖中央 `.jwt_secret` 或原部署的 `JWT_SECRET`。

冷授权检查文件头身份与数据库整文件 SHA-256，摘要为空、错文件或字节变化均拒绝签发，返回404且不写新授权。历史手工导入且缺摘要的资料需要管理员从可信备份确认原件后修复索引；系统不会自动接受未知文件。存储不可读取返回可重试503，权限不足仍优先返回403。

5分钟内的热授权缓存仍实时核对权限/吊销，但不重新读文件；已交付客户端的密钥不能离线收回。文件传输保留 Starlette 的范围下载及故障行为，客户端仍需要执行 KAF SDK 的解密与完整性校验。

当前 Compose 仍为单实例网关与持久卷。目录迁移的本地 TCP 验证不能证明 NFS、多主机副本、跨账号公共资料目录或云端上线；这几项需要各自部署设计与实测。备份操作继续遵循 README 的停机一致快照步骤。
# 发布提交的连接故障

SQLAlchemy 原生事务已关闭且会话健康时，新发布会通过独立会话核对本次资料的行主键、文件摘要、来源、内容与访问元数据。全部匹配后返回原资料编号；不会重试 COMMIT 或重新打包。

无法核实的连接故障返回 HTTP 503，`detail.code=publication_outcome_unknown`，并带 `file_id` 和 `status_url`。先用当前账号查询该资料，再决定是否重试；503 不表示数据库一定回滚。文件保留供核查，404 也不证明先前未完成的事务永远不会提交。该响应不带自动重试提示。取消、程序错误和非连接类数据库错误沿用原异常。外部事务、失败事务和旧对象更新不自动推断成功。此能力不保证真实断网恢复或多主机文件共享，仍需部署实测。
